# Paseo 0.15.2: per-user server on Idli, real Muse, driven through the UI

Architecture B shape, built locally on the DGX. Nothing public was used, and no IO service,
tunnel, DNS record or Muse setting was changed. The evaluation on `io_silo_untested` was not touched.
I used my own container names, networks and ports, and kept runtime state in a private scratch directory.

## Setup

- **Image.** `ghcr.io/getpaseo/paseo:0.15.2@sha256:e12414fe…46e6` (arm64), plus IO's pinned Codex 0.154.0
  and `@anthropic-ai/claude-code@2.1.319`. See [Dockerfile](Dockerfile); built locally as `io-oss-paseo:0.15.2`.
- **Two users, two containers.** `io-oss-paseo-a` and `io-oss-paseo-b`. Each has its own home volume,
  workspace, random `PASEO_PASSWORD`, `--cap-drop ALL` plus the 5 capabilities the entrypoint needs,
  `no-new-privileges`, 3 GiB memory and 512 pids. The daemon runs as uid 1000 and serves its bundled web UI.
- **Networks.** One Docker `--internal` network per user (`io-oss-private` 172.31.77.0/24,
  `io-oss-private-b` 172.31.78.0/24). A container cannot reach the internet, DNS or the other user.
  - Checked from A: public TCP gives `ENETUNREACH`, DNS gives `EAI_AGAIN`, and B's daemon gives `ENETUNREACH`.
  - B started on A's network, where A could reach B's daemon (HTTP 200). I moved B to its own
    network before running B's task. Sharing one network is not tenant-safe.
- **Model route.** [model_proxy.py](model_proxy.py) listens only on each network's gateway on port 8183.
  It forwards to Muse on `127.0.0.1:8181` and logs source, path, model and user agent. Log:
  [../model-requests.json](../model-requests.json).
- **Configs:**
  - [codex-config.toml](codex-config.toml) sets a Responses provider, a 65,536-token context, compaction
    at 45,000, and analytics and plugins off. It also sets `danger-full-access`, because bwrap is
    unavailable in an unprivileged container, so the container is the boundary.
  - [paseo-config.json](paseo-config.json) turns off relay, MCP and voice. It pins the Codex and Claude
    model lists to `muse-glimmer-30b`, routes title generation to Codex/Muse, disables the other
    providers (including Meta's "Muse Code"), points Claude Code at Muse through `ANTHROPIC_BASE_URL`,
    and disallows `WebSearch` and `WebFetch`.
- **Client.** The daemon-served web UI (the same renderer as the desktop app), driven by Playwright
  Chromium from the host. Paseo publishes no Linux arm64 desktop (only x64 deb, rpm and AppImage),
  so the packaged desktop was not run here. Driver scripts: [ui-driver/](ui-driver/).
- **Egress capture.** tcpdump runs inside each container's network namespace for its whole life,
  including boot. Summary: [egress.txt](egress.txt).

## Authentication through Cloudflare Access (not tested end to end)

- **How Paseo authenticates.** The daemon's only credential is one shared password per daemon. It is
  checked on the WebSocket upgrade (`Authorization: Bearer` or the `paseo.bearer.<pw>` subprotocol) and
  again in the first hello message (`session-admission-auth.ts`). A router cannot add it transparently.
- **Workable shape.** Per-user daemons with no password, reachable only through an IO router that
  checks the Access JWT, maps issuer and subject to a container, and proxies HTTP and WebSocket.
- **Browser client.** The daemon serves the web UI on the same origin, so through Access the browser's
  `CF_Authorization` cookie rides along on the WebSocket upgrade. The browser client needs no change.
- **Desktop and mobile apps.** Direct connections have only host, port, SSL, password and a
  connection URI. There is no custom header or Access login, so the apps cannot pass Access as shipped.
  SSH remote hosts (`remoteSsh`) exist and could be tried with `cloudflared access ssh`.

## Gaps and costs

- **Stop.** Stop does not kill running commands.
- **Auto mode.** Claude's "Auto mode" is unusable without Anthropic's classifier. Private presets should
  default to "Always ask" or "Accept file edits".
- **Outage.** Codex outages are silent in the UI; Paseo needs a timeout and a message.
- **Desktop app.** There is no Linux arm64 desktop. Windows (x64/arm64), macOS (arm64/x64) and Linux x64
  binaries exist but were not run here.
- **Fresh logins.** No fresh Open-mode OAuth was tried. There were no credentials in these containers.
- **Patch size.** Upstream code was not patched at all. The Private preset is configuration only
  (the three files here) plus the router described above.
