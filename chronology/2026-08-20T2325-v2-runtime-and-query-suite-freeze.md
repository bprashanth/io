# V2 runtime reproduction and laptop-query suite freeze

An isolated `.venv-v2` runtime was created without global installs and pinned in `benchmarks/v2/requirements.txt`. It includes DuckDB 1.5.5, pandas 3.0.5, jsonschema 4.26.0, openpyxl 3.1.5, Playwright 1.62.0 and sqlglot 30.17.0. Chromium 151 was installed for the v2 runner. `/mnt/seagate` was verified as a separate 3.7 TB external drive with about 3.7 TB free; model downloads use `/mnt/seagate/io-models` without moving existing caches.

Two Qwen 3.8 27B Low reproductions used the old synthetic smoke only to validate the environment. The first completed all turns in four successful model calls, 162.94 recorded model seconds and $0.01795575. All original deterministic checks passed after the verifier stopped assuming one of three hard-coded derived-metric names. Human screenshot inspection nevertheless failed the run: the initial page contained two years per district but the plan encoded neither year nor another unique series, so the chart silently collapsed duplicate district rows while its filter said All.

A generic chart-key uniqueness invariant was added. It rejects any executed result where chart x/series keys do not uniquely identify rows, requiring the planner to add the remaining dimension, filter it or aggregate explicitly. The second reproduction repaired turn 1 correctly by using year as the series and completed turn 2. Its turn-3 hosted planner call exceeded 180 seconds. The runner itself also exposed stale error-state recording: a planner timeout was mislabeled as a critic timeout and reused the previous attempt's plan. Planner and critic transport failures are now recorded separately and never trigger semantic rewrites.

The frontier metadata serializer was tightened for v2. It now removes row counts, null counts and distinct counts as well as raw/admitted/min/max values. Only column names/types and structural workbook/PDF outline information remain.

The frozen isolated query gate is `benchmarks/v2/query-suite-v1.json`: six generic relational patterns with five terse paraphrases each, covering rate ranking, time change, two derived measures, cross-table join and missing-value handling. Exact result sets are computed in DuckDB; SQL text is not compared. The evaluator accepts only one read-only query, transpiles SQLite to DuckDB, executes with external access disabled, allows one syntax/execution repair and reports semantic mismatches separately.

XiYanSQL-QwenCoder-3B-2504 was selected as the first local candidate after verifying its official Apache-2.0 repository, 3B/BF16 size, SQLite/PostgreSQL/MySQL training and absence from hosted inference providers. Its official full-precision files are being downloaded to the external drive. This is a capability screen, not yet a Windows or quantized-footprint claim.
