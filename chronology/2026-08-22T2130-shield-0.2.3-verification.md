# Privacy shield 0.2.3: the laptop build verified in the real IDE, eleven defects closed

Took the laptop agent's 0.2.2 handoff and re-verified it here by driving the real
Antigravity IDE (1.107.0, arm64) through CDP with the packaged extension, as a
participant would: status-bar picker, Enable, relaunch modal, in-chat review,
`ok`, dashboard, follow-ups over the scholarship CSV, fitness workbook, WhatsApp
export and PDF, Disable, relaunch, cold start. Every wire probe returned zero
hits; every answer was correct and rehydrated. Evidence:
`benchmarks/runs/2026-08-22-antigravity-ide-shield-v2/`.

Routing on this build: 0.2.2's "setting before relaunch" approach works here too
(both language servers start with `--cloud_code_endpoint` = proxy). The env
variable is kept as well; the combination is what was measured working on both
the x64 laptop and the arm64 DGX.

Defects found and fixed (each reproduced first):

1. A block that looked like a table but pandas could not parse raised inside
   the review code; the exception escaped the handler and the IDE waited ten
   minutes ("network error"). Now: unparseable blocks are text, and any
   internal error returns a visible shield message instead of hanging.
2. Command error output and tuple-printed rows were reviewed as "tables"
   whose column names were data values ("'Vinod Mishra' (person_name)").
   Headers must now be credible: named, short, unique, label-shaped.
3. The daemon died during the relaunch (VS Code kills its extension host's
   children), so the new instance's login check hit ECONNREFUSED and the IDE
   showed "Log in" for the session. The daemon is now spawned via setsid/start
   outside the process tree and the relaunch helper waits for it to answer.
4. Disable surfaced Antigravity's own "Restarting server failed" toasts; the
   language-server nudge is no longer issued when a relaunch follows.
5. `--numbers 8` tokenised dates ("2026-08-22" → NUMBER_001). Spaces only.
6. Tab-indented `head` output was not recognised as a table and got the prose
   engine; indentation is stripped before detection.
7. Kept-column values were memory-only; after a daemon restart `Mulshi` (kept
   taluka, also a village) tripped the guard. Kept values persist with the
   decisions, and a new table whose column is mostly kept values is kept.
8. Real leak: `Follow up with GURLEEN SIDDIQUI at PHONE_632` in a Remarks
   cell — uppercase names were rejected by the shape filter. Names may be
   Capitalised, ALLCAPS or initials; a name before `at/on/(/, PHONE_…` is hidden.
9. Remarks-cell recall on the corpus ground truth rose from 164/182 to
   181/182 by trusting the model's person spans in data context (lowercase
   names, single first names at 0.45 in cells, leading "Guardian/Mr/Smt"
   stripped, initials and cue-word regexes), while village/address guesses
   are no longer minted from short cells (that produced junk like "shifted
   house" and guard false positives).
10. The WhatsApp export was classified as shell output because `dd/mm/yy`
    matched the path heuristic — prose names 0/291. Fixed (paths need
    letters); plus the chat-sender rule and in-text name propagation from the
    benchmark engine, which the shield had never received: 262/291 names,
    60/60 phones. GPS pairs followed by a full stop were missed: 9/9 now.
11. The egress guard now repairs before it refuses: a final vault substitution
    over the outgoing body makes consistency independent of walk order; it
    blocks only if a value still cannot be substituted.

Also: free-port selection (8765–8784) with the chosen port remembered, and the
relaunch helper stops the daemon on Disable so nothing lingers.

Still open: villages inside prose (13/25 on the report) unless the same names
appear in a table; tokenisation removes name semantics, so the model can
mislabel which of two hidden names is the student vs the parent; first
redaction of a long history after a daemon restart costs 10–25 s; macOS and
Windows helper paths untested here.
